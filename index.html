What is IT security?

💡 Answer
IT security is the practice of protecting information, computers, networks, applications and digital services from unauthorized access, disclosure, alteration, destruction and disruption.

SAQ 2

Why is IT security important in modern organization?

💡 Answer
Organizations depend on digital systems for communication, finance, customer records and daily operations. Security protects information, business continuity, reputation and trust.
🧠 Easy samajh

SAQ 3

Define Cyber Threats.

💡 Answer
A cyber threat is a potential malicious event, actor or activity that can exploit a vulnerability and harm a system, network, application or data.
🧠 Easy samajh
Examples: phishing, malware, ransomware, credential theft and denial-of-service.

LAQ 1

What is IT security & Discuss its importance.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. IT security protects information and IT resources such as computers, networks, applications, devices and digital services from unauthorized access, disclosure, alteration, destruction and disruption.
  2. The main objectives are confidentiality, integrity and availability. Confidentiality protects secrets, integrity protects correctness, and availability keeps services usable.
  3. IT security is important because organizations hold customer data, credentials, financial information, intellectual property and operational systems. A compromise can cause financial loss, downtime, fraud, legal consequences and reputational damage.
  4. Important controls include authentication, authorization, least privilege, encryption, firewalls, secure configuration, patch management, endpoint protection, backups, logging, monitoring, security awareness and incident response.
  5. Example: A company protects its customer database using access controls, encryption, patching, monitoring and backups.
  6. Exam conclusion: IT security is a business requirement, not merely a technical function. Layered controls reduce the chance and impact of compromise.
LAQ 2

Describe the evolution of cyber threat with example.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Cyber threats have evolved from relatively simple viruses and worms into organized, automated and targeted attacks.
  2. Early attacks often spread by infecting files or exploiting network weaknesses. Later, attackers increasingly targeted web services, email, credentials and vulnerable applications.
  3. Modern attacks can combine phishing, credential theft, privilege abuse, lateral movement, data theft and ransomware. Cloud services, mobile devices and supply chains have also expanded the attack surface.
  4. Example: An attacker may send a convincing phishing message, steal an employee's credentials, enter a corporate service and then steal or encrypt valuable data.
  5. Exam conclusion: Because threats evolve continuously, organizations need continuous patching, identity protection, monitoring, backups, awareness and incident response.
LAQ 3

Explain the CIA Triad with real life example.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. The CIA Triad consists of Confidentiality, Integrity and Availability.
  2. Confidentiality: only authorized people can view information. Example: only authorized hospital staff should access a patient's medical record.
  3. Integrity: information must remain accurate and protected from unauthorized modification. Example: an online banking balance must not be altered illegally.
  4. Availability: authorized users must be able to access systems when needed. Example: a hospital or emergency-service system must remain operational during critical situations.
  5. Banking example: encryption and access controls support confidentiality; transaction controls and audit logs support integrity; redundancy, backups and disaster recovery support availability.
  6. Exam conclusion: A secure system must balance all three objectives.
LAQ 4

Discuss the principles of confidentiality, integrity and availability in detail.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Confidentiality prevents unauthorized disclosure. Controls include authentication, authorization, least privilege, encryption and data classification.
  2. Integrity protects data and systems from unauthorized or accidental modification. Controls include access control, hashes/checksums, digital signatures, validation, audit logs and version control.
  3. Availability keeps systems usable when required. Controls include redundancy, backups, monitoring, capacity planning, fault tolerance, disaster recovery and protection against denial-of-service conditions.
  4. Example: In a university examination system, confidentiality protects question papers and student records; integrity protects marks; availability keeps the portal accessible.
  5. Exam conclusion: Focusing on only one property is insufficient; effective security considers all three.
LAQ 5

Explain physical security principles & their role in IT security.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Physical security protects people, facilities and hardware from physical threats. A technically secure server can still be compromised if an attacker can physically reach it.
  2. Important principles are deterrence, detection, delay, access control and response. Fences and barriers deter/delay; CCTV detects; guards respond; locks, RFID and biometrics restrict access.
  3. Environmental protection is also important: fire detection/suppression, temperature and humidity control, power protection, water-leak controls and safe equipment placement.
  4. Example: A server room may use fencing, guards, badge/biometric entry, CCTV, locked racks and environmental monitoring.
  5. Exam conclusion: Physical security is a necessary layer of IT security because physical access can bypass many logical controls.
LAQ 6

Describe the process of conducting a site survey for security assessment.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Step 1 — Define scope: identify buildings, rooms, assets and assessment objectives.
  2. Step 2 — Identify critical assets: locate servers, network equipment, sensitive records, backup media and critical power systems.
  3. Step 3 — Inspect perimeter: examine fences, walls, gates, lighting, parking areas and possible bypass routes.
  4. Step 4 — Inspect internal controls: review doors, locks, access cards, biometrics, visitor procedures and restricted rooms.
  5. Step 5 — Review surveillance: check CCTV coverage, recording, motion sensors, alarms and blind spots.
  6. Step 6 — Review environmental risks: fire protection, water exposure, temperature, humidity, power and emergency systems.
  7. Step 7 — Assess findings: identify threats and vulnerabilities and estimate likelihood/impact.
  8. Step 8 — Recommend and document: prioritize controls and produce maps, observations, evidence, risk ratings and an action plan.
LAQ 7

Explain Risk assessment techniques in physical security.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Risk assessment identifies what can go wrong, how likely it is and how serious the result would be.
  2. Asset identification: list critical people, facilities, equipment and information.
  3. Threat identification: consider theft, unauthorized entry, vandalism, fire, flood, power failure and other relevant hazards.
  4. Vulnerability assessment: identify weak doors, poor lighting, CCTV blind spots, weak visitor controls and similar weaknesses.
  5. Likelihood and impact: estimate probability and consequence; a risk matrix can classify results as low, medium, high or critical.
  6. Qualitative assessment uses descriptive ratings and expert judgment. Quantitative assessment attempts numerical estimates.
  7. Risk treatment: avoid, mitigate/reduce, transfer/share, or accept risk within organizational tolerance.
LAQ 8

Discuss various threat modeling techniques.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Threat modelling asks: what are we protecting, what can go wrong, how could an attacker achieve it, and which controls reduce the risk?
  2. STRIDE: Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service and Elevation of Privilege.
  3. Attack trees: start with an attacker goal and break it into alternative paths that could achieve that goal.
  4. DFD-based modelling: map processes, data stores, data flows and trust boundaries, then examine threats at important boundaries.
  5. Abuse/misuse cases: describe how a legitimate feature could be intentionally misused.
  6. Example: For online banking, spoofing may involve stolen credentials, information disclosure may expose account data, and denial of service may make the service unavailable.
  7. Exam conclusion: Threat modelling is most valuable early in design because weaknesses are cheaper to fix before deployment.
LAQ 9

Explain different types of perimeter security.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Perimeter security protects the boundary of a site and controls entry and exit.
  2. Physical barriers: fences, walls, gates, bollards and barriers deter and delay unauthorized access.
  3. Controlled entry: checkpoints, turnstiles, manned gates and electronic locks restrict access to approved routes.
  4. Surveillance: CCTV and lighting help detect activity and provide evidence.
  5. Intrusion detection: sensors and alarms identify unauthorized movement or entry.
  6. Personnel and visitor controls: guards, identification checks, visitor badges and escort procedures improve control.
  7. Exam conclusion: Layered perimeter security should deter, detect, delay and support response rather than relying on a single control.
LAQ 10

Discuss access control systems such as biometrics and RFID.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Access control decides who is permitted to enter an area or use a protected resource.
  2. RFID/card: An electronic credential is read by a reader; the system checks authorization and grants or denies access.
  3. Biometrics: Identity is verified using characteristics such as fingerprints, facial features or iris patterns.
  4. Typical flow: present credential → capture/read → verify → check authorization policy → grant/deny → log the event.
  5. Advantages: centralized control, access logging and easier revocation than physical keys.
  6. Risks: stolen cards, credential sharing, privacy concerns, false acceptance/rejection and system failures.
  7. Best practice: combine appropriate authentication strength, least privilege, visitor controls, logging and monitoring.
LAQ 11

Explain surveillance system like CCTV & Motion sensor.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Surveillance systems observe areas to deter, detect and investigate suspicious activity.
  2. CCTV: Cameras capture live or recorded video. A complete system includes cameras, recording/storage, monitoring and controls over recordings.
  3. Motion sensors: Detect movement or changes in an area and can trigger alarms or recording. Technologies may include infrared or microwave sensing.
  4. Design points: coverage, camera placement, lighting, blind spots, storage/retention, access to recordings and time synchronization.
  5. Example: A restricted server room can use CCTV for evidence and a motion sensor to alert security to movement outside expected hours.
  6. Limitations: blind spots, false alarms, lighting problems, storage requirements and privacy concerns.
LAQ 12

What is host security? Explain host hardening techniques in detail.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Host security protects individual computers, servers and endpoint devices. Host hardening reduces the attack surface.
  2. Remove unnecessary software/services: fewer components mean fewer possible weaknesses.
  3. Patch OS and applications: reduces exposure to known vulnerabilities.
  4. Secure accounts: strong authentication, least privilege and removal of unused accounts.
  5. Configure host firewalls: restrict unnecessary network connections.
  6. Endpoint protection: antivirus/anti-malware and behavior monitoring can detect malicious activity.
  7. Logging/monitoring: records security events for detection and investigation.
  8. Secure data and backups: protect sensitive files and recovery copies.
  9. Baseline configuration: standardize secure settings and check for configuration drift.
  10. Example: A production server should expose only required services, restrict administrator access, log security events and receive tested patches.
LAQ 13

Discuss patch management & its importance in security system.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Patch management is the lifecycle of identifying updates, assessing risk, testing, deploying and verifying them.
  2. Process: maintain asset inventory → identify patches → prioritize by severity/exploitability/criticality → test → deploy → verify → document exceptions.
  3. It is important because attackers often exploit known vulnerabilities. Unpatched systems therefore create avoidable exposure.
  4. Patch priority should consider the vulnerability, whether it is actively exploitable, how exposed the system is and how important the asset is.
  5. Example: A critical vulnerability on an internet-facing server normally deserves higher priority than a low-risk issue on an isolated test machine.
  6. Exam conclusion: Good patch management reduces attack surface while controlled testing limits operational disruption.
LAQ 14

Explain end point protection solutions such as antivirus & anti-malware.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Endpoint protection secures laptops, desktops, servers and other endpoint devices against malicious activity.
  2. Antivirus traditionally uses signatures and related methods to detect known malware. Modern endpoint protection may also use heuristics, behavior analysis and reputation signals.
  3. It can provide real-time scanning, quarantine, malicious-download protection, behavior monitoring, alerts and centralized management.
  4. Benefits: faster detection, reduced malware execution and better endpoint visibility.
  5. Limitations: no tool detects every attack. Endpoint protection must be combined with patching, least privilege, application control, backups, network controls and user awareness.
  6. Example: Suspicious ransomware behavior may be detected and the process blocked or quarantined.
LAQ 15

Describe operating system security mechanism.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Operating-system security controls users, processes, files, devices and system resources.
  2. Authentication verifies identity. Authorization determines permitted actions. File permissions control reading, writing and execution.
  3. Process isolation and privilege separation limit how much one process or account can affect others.
  4. Logging records security-relevant events. Hardening disables unnecessary services, applies patches and restricts administrative privileges.
  5. Additional protections can include host firewalls and memory/execution defenses.
  6. Core principle: least privilege—users and processes should receive only the permissions needed for legitimate work.
LAQ 16

Explain user authentication & access control method.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Authentication answers “Who are you?”; authorization/access control answers “What are you allowed to do?”
  2. Authentication can use knowledge factors (password/PIN), possession factors (token/device) and inherence factors (biometrics). Multi-factor authentication combines independent factors.
  3. After authentication, access-control models enforce permissions. Common models include DAC, MAC, RBAC and ABAC.
  4. RBAC example: A Finance role may access finance applications while an HR role receives a different permission set.
  5. Best practices include least privilege, strong authentication, secure credential storage, session protection, periodic access reviews, timely revocation and logging.
LAQ 17

Discuss file system encryption & its benefits.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. File-system encryption protects stored data by converting readable plaintext into ciphertext using a cryptographic key.
  2. Benefits: helps protect laptops, disks, removable media, backups and sensitive server storage if the storage device is lost or stolen.
  3. Important considerations include key management, recovery procedures, access control and protecting systems that can legitimately decrypt the data.
  4. Encryption primarily supports confidentiality of stored data. It does not by itself stop an already-authorized but compromised account from reading or modifying files.
  5. Example: An encrypted laptop stolen while powered off should not expose protected disk contents without the required key.
LAQ 18

Explain secure coding principle with example.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Secure coding means building software so common security weaknesses are prevented during development.
  2. Input validation: treat external input as untrusted and validate type, length, format and range.
  3. Output encoding: encode data for the context where it is displayed.
  4. Parameterized queries: use them instead of concatenating untrusted data into SQL statements.
  5. Authentication/authorization: verify identity and enforce permissions on the server side.
  6. Least privilege and safe errors: give applications only needed permissions and avoid exposing secrets/internal details in error messages.
  7. Dependencies: keep third-party libraries supported and updated.
  8. Example: A database query should pass a username as a parameter rather than inserting raw user input into a SQL string.
LAQ 19

What is application whitelisting? Discuss its advantages and limitations.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Application whitelisting allows only explicitly approved applications, binaries or software components to execute.
  2. Advantages: reduces unauthorized software execution, helps limit malware, supports tightly controlled systems and gives administrators strong application control.
  3. Limitations: allow-lists require maintenance; legitimate updates may need approval; dynamic applications/scripts can complicate policy; and a trusted application may still be abused if compromised.
  4. Good implementation: maintain an accurate inventory, use change management, test policies, monitor execution and define an exception process.
  5. Exam conclusion: Whitelisting is a strong preventive layer but should be combined with patching, endpoint detection, identity security and secure configuration.
LAQ 20

Discuss best practices for application security in modern system.

✍️ 10-mark formula: Definition → Key points → Process/Types → Example → Conclusion
  1. Application security should be built throughout the software lifecycle rather than added only at the end.
  2. Secure design: define security requirements and perform threat modelling early.
  3. Secure coding: validate inputs, use safe APIs, parameterized queries, secure authentication, authorization and careful error handling.
  4. Dependency/supply-chain security: inventory third-party components, update them and protect build/deployment pipelines.
  5. Secrets management: do not hard-code passwords, API keys or cryptographic secrets in source code.
  6. Testing: use code review, security testing, vulnerability scanning and appropriate penetration testing.
  7. Identity and data protection: least privilege, strong authentication, secure sessions, encryption where appropriate and protected keys.
  8. Monitoring and response: log security-relevant events, monitor suspicious behavior and maintain an incident-response process.
  9. Exam conclusion: Application security is continuous—design, code, test, deploy, monitor and maintain.
